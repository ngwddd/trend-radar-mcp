# v0.3 设计说明：两轮完成 + 传播分重做

> 目标：把「模型要跑几轮」当成一等指标，并把权重里过于理想化的部分拆掉。
> 数字来自本机实测（2026-10-19）。

---

## 1. 流程为什么还是长

v0.2 的典型链路是 4 轮模型往返：

```
判类 → radar_scan → radar_entries → 写简报
```

每一轮都包含一次模型生成 + 一次工具调用。v0.3 砍掉两轮：

1. **判类进工具**：`radar_scan(query=...)` 内部调 `classify_request`；
   命中单一类且置信度 ≥0.7 就用该类，否则 broad。显式 `domain` 永远优先。
   返回 `scope_source = auto / explicit / auto-broad`，可审计。
2. **扫描直接带摘要**：`briefs` 参数把 core/watch 前 3 条摘要内联进返回
   （默认 240 字/条）。多数简报一次调用就够写，不需要 `radar_pack`。

于是典型链路变成 2 轮：

```
radar_scan(query) → 写简报
```

`radar_pack`（不够时取更多正文）和 `radar_check`（发布前量关联度/给补搜打分）
变成**按需**的旁路，不是必经步骤。

工具数：6 → 3。

---

## 2. 速度：瓶颈不在并发度

42 个源已经是 16 线程并发 + 按主机限速。冷启动的墙钟由**最慢的两三个源**决定：

| 源 | 耗时 | 说明 |
|---|---|---|
| `arxiv-ai` | 18 s 量级 | 4 个分类 × 3 s 礼貌间隔，不能压 |
| `geekpark` / `tmtpost` | 1–14 s | 网络抖动，偶发拖尾 |
| 其余 | < 5 s | |

所以 v0.3 加的是**开关**而不是更多线程：

- `deep=false`（默认）跳过 arXiv API（`kind=atom`），它的 RSS 仍在抓；
- 源级缓存 5 分钟，热启动 **0.2 s**；
- 连续 3 次空源 → 12 小时跳过；死路不重试。

实测：单类 2–9 s，broad 冷启 13 s（网络抖动时），热 0.2 s。
继续加线程不会更快——慢源是串行礼貌等待，不是并发不足。

## 3. 权重哪里「过于理想化」

| # | 问题 | 后果 |
|---|---|---|
| 1 | 三条互斥公式（source-tier / social / platform） | 同一件事三套算法，维护必然漂移 |
| 2 | corroboration 同时加 truth 和 comm | 双重计数：两个低质转载就能把弱证据抬过真值闸门 |
| 3 | comm 只看独立来源**数量** | 两个 IT之家转载 = Reuters + Nature，同为 0.60 |
| 4 | 0.6 硬阈值 | 0.59 与 0.61 处置相反，边界样本无声消失 |
| 5 | 社会域权重反转（0.3 平台 / 0.7 形式） | 两把尺子，跨域不可比 |

## 4. v0.3 的评分模型

### truth（真值）

```
truth = 0.4 × S + 0.6 × E
```

- `S` = 源层级（期刊/媒体）或平台层级（社会域）；
- `E` = 证据层级（peer-reviewed / official / preprint / journalism…）；
- **不再加 corroboration bonus**：印证是「传播」信号，不是「真值」信号。
  它现在只影响 comm，避免同一件事被加两次。

保留的硬规则：撤稿 → 0.05 短路；关注声明 → 上限 0.45；更正 → 上限 0.60；
热榜 → 0.45 封顶；无正文 → 0.50 封顶；促销 → 降 0.25/0.15；front-matter → journalism。

### comm（传播）

```
mass = 1 + Σ(其他独立源的层级) / 0.60
comm = 插值( [1→0.30, 2→0.60, 3→0.72, 4→0.80, 5→0.88], mass )
```

含义：

| 情况 | comm | 过闸？ |
|---|---|---|
| 只有原发（哪怕 Nature） | 0.30 | 否（单源硬证据通道另算） |
| +1 个平均媒体转载 | 0.60 | 是 |
| +1 个低质站转载（0.45） | 0.525 | **否** |
| +1 个顶刊/通讯社（0.90） | 0.66 | 是 |
| +2 个平均转载 | 0.72 | 是 |

**单源硬证据通道**保留：`peer-reviewed` + truth ≥0.6 → 进核心区，标
`single_source_hard_evidence=true`，引用时必须写「单源」。

### borderline 带

`|truth − 0.6| ≤ 0.05` 或 `|comm − 0.6| ≤ 0.05` 的条目打 `borderline=true`，
不改变分桶，但要求模型/人复核后再引用。这样 0.59 与 0.61 不再被当成两个世界。

### 为什么不做「学习权重」

用状态库统计每个源的历史撤稿率/印证率来自动调权重，方向是对的，但需要
**每源 ≥20 条**样本才稳定；现在样本不足，自动调权会变成另一种过拟合。
先做可解释的质量加权，校准层留到 0.4。

## 5. 预算

| 指标 | v1 skill | v0.2 | v0.3 |
|---|---|---|---|
| 模型轮次（典型） | 8 阶段 | 4 | **2** |
| 扫描响应 | 158 KB | 5.2 KB | **5.9–7.3 KB**（含 3 条摘要） |
| 工具数 | 1 skill | 6 | **3** |
| 冷启动 | ~50 s | 10.7 s | **2–9 s 单类 / 13 s broad** |
| 热启动 | 无 | 0.3 s | **0.2 s** |

内联 briefs 多花约 1.5 KB，但省掉一整轮模型往返；一次往返的成本远高于 1.5 KB。

## 6. 取舍与风险

- **默认不抓 arXiv API**：省 10–18 s，代价是拿不到 API 的完整摘要；
  需要时 `deep=true`。RSS 公告仍在。
- **质量加权会让「两家小站互转」不再过传播闸门**：这是有意的，但它也会让
  部分社会新闻降级到待观察区——宁可标出来，不要假装印证过。
- **auto scope 可能判错**：分类器是关键词表，措辞一变就可能落到 broad。
  返回里带 `classification` 与 `scope_source`，模型可显式覆盖。
- **borderline 增加复核成本**：只在 0.55–0.65 之间触发，实测占比很小。
