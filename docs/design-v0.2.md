# v0.2 设计说明：digest 优先、broad 兜底

> 目标不是「功能更多」，而是**同一个研判任务消耗的上下文更少、等待更短、结论更纯**。
> 所有数字都来自本机实测（2026-10-19），不是估算。

---

## 1. 要解决的三件事

| 问题 | v0.1 的实际表现 | 代价 |
|---|---|---|
| 模型判不进三类时无路可走 | `domain` 必填、只接受 social/science/ai | 只能猜一个类，猜错下游无法发现 |
| 先给全量、再让模型筛 | `radar_scan` 返回 ~11 KB compact entries | 模型读了一堆最终不会写的条目 |
| 空源/慢源每轮都重试 | 42 源全发，失败源下轮照发 | 每轮固定浪费请求与超时槽 |

外加一个实测 bug：`social + authority` 在该域**没有任何权威源**，旧逻辑会返回 0 个源，
整轮空跑却看不出异常——这比报错更危险。

---

## 2. 设计原则

1. **工具给「决策所需的最小信息」，不给「全部信息」。**
   扫描返回 digest（id + 分数 + 标题），正文按 id 取。
2. **上限写进 schema，不写在提示词里。**
   模型会忘记提示词，但客户端会把 `maxItems` 一起送进上下文。
3. **宽搜是显式动作，不是默认。**
   broad 更贵，只在「判不了」或用户要「全面搜」时使用。
4. **判断留在模型侧。** 不把 LLM 塞进工具里——那会变成一个看不见的第二代理。

---

## 3. 新流程

```
需求
  │
  ├─ 模型：判 scope ── 三类之一 ──┐
  │                    └─ 判不了 → broad（42 源全开）
  ▼
radar_scan（工具内部）
  ├─ 选源：scope × streams；跳过 known-dead；跳过 empty_streak ≥ 3（12h）
  ├─ 并发：16 线程 + 按主机限速（arXiv 3s / Crossref 0.35s）
  ├─ 缓存：源级 5 分钟；命中 → 0.3s 返回
  ├─ 归一化：RSS / Atom / Crossref / 热榜 → 时间窗 → 事件级去重
  ├─ 状态：SQLite first_seen / times_seen → is_new；source_health
  ├─ 评分：truth / comm → 0.6 闸门 → 5 桶
  └─ digest：每桶 top N，≤ 6.5 KB（无摘要）
  ▼
模型：读 digest → 选要写的 id（≤ 20）
  ▼
radar_entries(ids, fields=["summary"]) —— 只取那几条（~3 KB）
  ▼
模型：写简报 + 自检（关联度、冲突、覆盖披露）
  ▼
输出到聊天
```

---

## 4. 工具契约（硬限制）

| 工具 | 上限 | 返回 |
|---|---|---|
| `radar_scan` | 响应 ≤ 6.5 KB；`top` ≤ 10/桶 | digest + 统计 + 覆盖告警 |
| `radar_entries` | `ids` ≤ 20；`limit` ≤ 50；摘要 ≤ 800 字 | 只含请求的字段 |
| `radar_sources` | — | 注册表 + 死路 + 连续空源 |
| `radar_score` | 条目 ≤ 20；必须有 `url` | 分数 + 分桶，不回正文 |
| `radar_relevance` | 条目 ≤ 50；关键词 ≤ 8 | 覆盖率 + 是否需二次搜寻 |
| `radar_history` | `limit` ≤ 50 | first_seen / times_seen |

**默认字段**：`radar_entries` 默认只给 `scores + flags`，要正文必须显式写
`fields=["summary"]`——这是「提纯度」的开关。

## 5. 实测

| 指标 | v1 skill | v0.1 MCP | v0.2 MCP |
|---|---|---|---|
| 单次扫描响应 | 158 KB（compact JSON） | ~11 KB | **5.2 KB** |
| 取正文 | 全量已进上下文 | 全量已进上下文 | **按 id 取，3 条 ≈ 2.9 KB** |
| 冷启动（broad） | 串行 ~50 s | — | **10.7 s**（42 源） |
| 热缓存 | 无 | 0.3 s | **0.3 s** |
| 「新」的判断 | 模型猜 | first_seen | first_seen（修正时区比较） |
| 空跑 | 无提示 | 无提示 | `stream_fallback=true` 显式标记 |

一次完整研判的上下文粗算：`5.2 KB + 3 KB + 写作 ≈ 10 KB`，约为 v1 的 **1/15**。

---

## 6. 取舍

- **多一次调用换更少的 token**：digest → entries 是两次调用，但第二次只取 3–8 条；
  相比「一次拿 11 KB 再筛」，净省一半以上。
- **空源黑名单可能误伤**：连续 3 次 0 条才拉黑，且 12 小时后自动解除；
  一次失败（网络）不计入空源。
- **broad 不默认**：它把 42 个源全打开，冷启约 10.7 s；单类通常 5–8 s。
- **不把 LLM 放进工具**：判断、写作、追问用户仍在模型侧——工具只做确定性部分。
